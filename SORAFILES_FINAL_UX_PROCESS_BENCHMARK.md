# SoraFiles V6 Final UX and Process Benchmark

The design benchmark used the existing SoraFiles visual language and the prompt's named workflow references. A UI change was retained only when it reduced ambiguity, improved direct manipulation, or made the same capability usable on mobile. Cosmetic imitation was rejected.

| Tool | Old SoraFiles Workflow | Best Reference | New SoraFiles Workflow | Why Better | Verified |
|---|---|---|---|---|---|
| All tools | Upload surfaces and post-upload layouts varied by tool. | SoraFiles Image drop zone; premium desktop workspaces | One premium drop-or-browse contract across every primary tool, then direct continuity into an adaptive workspace. | Users recognize the same entry point and do not lose the selected file when the editor opens. | Unit contract plus all 26 real UI flows. |
| Shared desktop tools | Controls and result state could feel like separate forms. | Professional “canvas + inspector” workstations | Source/canvas remains visible while the contextual inspector and result actions occupy stable regions. | Clear file-to-preview-to-result continuity with fewer scroll/context losses. | 1440 px responsive coverage and downloaded output checks. |
| Shared mobile tools | Desktop columns compressed into a long, hard-to-navigate page. | Mobile full-screen editor patterns | File, preview/canvas, and adjust/result panels are reachable through explicit mobile navigation; controls retain touch-sized targets. | The preview can be checked while editing instead of becoming hidden above long controls. | Dedicated 390×844 audit passed every workspace family. |
| Doc Scanner | Automatic crop selection implied that SoraFiles had decided the document boundary. | Scanic direct correction; mobile scanner studios | Upload opens a dedicated page/canvas/adjust studio. Full image is the default; **Adjust corners** is opt-in; touch handles, reorder, replace, rotate, and export remain available. | Eliminates destructive-looking automatic intent while preserving a fast correction path. | Multi-page Firefox flow, manual handle movement, mobile navigation, valid adjusted two-page PDF. |
| Doc Scanner adjustments | Presets hid the exact visual outcome and fine controls were incomplete. | Photo-editor tonal inspectors | Exposure, highlights, shadows, contrast, brightness, black point, definition, sharpness, noise reduction, and saturation update live preview/thumbnails and the final export. | Users can see the result at the moment a slider changes; page-specific values persist and reset predictably. | Seven non-default controls and adjusted export validated at 390 px; pixel engine unit tests pass. |
| Edit Image | A smaller set of edits did not share scanner-quality tonal control. | Compact professional image inspectors | Uses the same light/detail stack, live canvas, presets, saturation, undo/redo, crop, rotate, flip, and verified export. | Familiar controls behave identically across related tools. | Ten controls, undo/redo, crop, and changed-pixel WebP passed. |
| Sign PDF | Placement risked becoming a form-driven coordinate task. | Pagelea, Sejda, Adobe-style direct placement | Signature is uploaded/drawn, placed on the PDF itself, dragged, resized, undoable/redoable, optionally saved locally, and available through mobile panels. | Direct manipulation makes placement and scale legible before export. | Full pass, desktop/mobile screenshots, focused final retry, valid rendered PDF. |
| Watermark PDF | Text/logo configuration could be disconnected from placement. | Direct PDF overlay editors | Live watermark object can be selected, dragged, resized, and page-targeted on the actual document canvas. | Preview and export coordinates share one mental model. | Text and transparent-logo paths passed; output preview nonblank. |
| Merge / split / rotate / remove pages | Page actions behaved as individual forms. | Adobe/Smallpdf/iLovePDF page organizers | Shared page-oriented workspace shows thumbnails, selection/order, and contextual actions without rasterizing source pages. | Page intent is visible before processing and remains usable on narrow screens. | Page order/count/rotation independently parsed from downloads. |
| Remove Background | Third-party model fetch failure could surface only as generic processing failure. | Local-first resilient inference | Same-origin cacheable model route is attempted first, with an explicit vendor fallback; editor and download remain local. | Privacy extensions are less likely to block initialization, and failures do not masquerade as success. | Real foreground/transparency output passed twice in V6 Firefox runs. |
| Image conversion/compression | Native codecs were fast but left material JPEG/PNG efficiency unused. | Upstream Squoosh/jSquash codecs | The same UI now lazy-loads MozJPEG/OxiPNG only when relevant, displays the same result flow, respects hard targets, and transparently falls back. | Better outputs without adding mode clutter or compromising job completion. | Integrated real JPG/PNG/WebP conversion plus normal/target compression passed. |

## Design decision

The final direction is a **pocket workstation**: calm SoraFiles typography and color, one recognizable upload surface, a persistent file/canvas relationship, a focused inspector, and explicit mobile panels. No new decorative design system or competitor clone was introduced.
