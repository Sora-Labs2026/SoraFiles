# Guides and content operations

Guides use the typed `src/data/guides.ts` registry with the six commissioned articles in `src/data/guides-first-batch.ts` and Astro static routes. No CMS, database, article generator or production fixture is installed. Approved content uses escaped typed blocks: H2/H3 headings, paragraphs with safe inline links, lists, tables, images and callouts. The template owns H1 and supports references, visible author/publication/review information, related tools/guides and a target-tool CTA.

Records support slug, title, description, primary/secondary queries, intent, funnel stage, category, tags, target/related tools, related guides, author, publisher, status, publication/modification/review dates, canonical, social image, indexability, references, locale and translationOf. Categories are PDF, Images, Privacy & Security, Troubleshooting and File Formats. Statuses are idea, brief, draft, review, approved, published and archived. The publisher is the existing Sora Labs identity; authors and dates must reflect real editorial work.

Only published English records generate `/guides/{slug}`. Published records with `indexable: false` render noindex and remain excluded from discovery modules and sitemap. Drafts, archived records and all other statuses generate no public route and resolve through the normal site 404. There is no public preview endpoint: preview by rendering the template in tests or local development. Noindex is not access control. No draft content is shipped to browser bundles.

Only published AND indexable English records enter the sitemap, related modules and guide index. `/guides` returns an honest empty 200/noindex page until such records exist. English navigation/footer link to this hub; localized navigation has no Guides entry. The template emits no translated URLs or hreflang. Non-English records currently fail validation.

The existing Layout owns canonical, robots and social metadata; the guide template supplies Article and BreadcrumbList JSON-LD from visible fields. Tool references use real registry IDs resolving to canonical slugs. Text is escaped; typed blocks cannot insert raw HTML.

Run `node --experimental-strip-types scripts/validate-guides.mjs`. The production build runs this before Astro. Blocking checks cover required fields, identities, canonicals, dates, status/indexability, locale, relationships, image sources/alt/dimensions, tables and heading structure. Duplicate slugs/canonicals and normalized titles/primary queries/descriptions are errors. Token-set overlap and matching tool/intent combinations produce warnings, never a score or automatic merge. Local assets are checked on disk; external availability and factual claims still require human review.

Before publishing: verify claims/references, resolve errors and overlap warnings, obtain human approval, then explicitly set status and indexability and run the production build. Merely setting approved does not publish.

`data/content-operations.ts` defines the empty keyword registry and content-brief schema. Missing metrics remain null or absent. These operations records are not imported by site pages or client modules.

For ordinary Search Console CSV exports, run `node --experimental-strip-types scripts/import-search-console.mjs path/to/export.csv [minimumImpressions=100] [maximumClicks=5]`. Put private source exports under ignored `data/search-console/`; normalized JSON always goes in its ignored `private/` directory. The parser supports BOM, quoted commas/newlines, escaped quotes and common English header variants. Malformed CSV and invalid metrics fail. Empty fields stay null; metrics are not inferred. CSV strings are serialized as JSON, never executed as HTML or formulas.

Opportunity thresholds are configurable triage cutoffs, not universal CTR benchmarks. Unexpected queries are compared with registered keywords, guide queries and tool names. Possible cannibalization requires actual query/page pairs on multiple known canonical URLs. Separate Query and Page exports cannot establish these pairs; the importer never invents a join. Noncanonical landing pages require review.

IndexNow keeps the existing public key and search submission command. Its allowlist comes from real localized routes plus indexable guides. Aliases, malformed URLs, credentials, queries, fragments, staging and unknown routes are rejected; URLs are deduplicated and batched at at most 10,000. External submission requires `--live`; checks use `--dry-run`. Provider errors are recorded and nonfatal unless the existing explicit `--strict` option is supplied. HTTP 202 is recorded as pending key validation, not indexing success. Submission outcomes are recorded in the release report. Protocol: https://www.indexnow.org/documentation.
